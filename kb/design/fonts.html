Which fonts actually load

Profolio KSA paints in Figtree.

This page said the opposite until the design QA's pixel diff caught it, so the evidence is worth stating plainly. In the product's own render (data/live/listings.capture.json), 1,698 of 1,708 elements compute

Figtree, "Droid Arabic Kufi", sans-serif

The other ten are icomoon, the currency glyph font. Nothing computes Lato.

Where each one comes from

src/theme/index.js:306the antd v5 token fontFamily: 'Figtree, Droid Arabic Kufi, sans-serif' — applied through ConfigProvider with cssVar, so it reaches everything
src/hooks/useAppInit.jsfetches Mukta + Figtree from Google Fonts whenever !isMemberArea — i.e. for Profolio proper
src/hooks/useAppInit.jsalso injects arabic-font.css, currency-font.css, lato-font.css for every bayut session
constants.js FONT_FAMILY_LITELato, Droid Arabic Kufi, sans-serif — the lite / member area, not this product

So Lato is downloaded, and paints nothing here: only FONT_FAMILY_LITE and the lite footer in layout/styled.js name it.

Weights

Figtree is a variable font, 300–900. Every weight in that range is a real face. .fw-500 and .fw-600 are not synthesised — an earlier version of this page said they were, which was true of Lato and never true of what ships.

Arabic

Droid Arabic Kufi is second in the stack and KSA ships Arabic first (LANGUAGES[0] is ar), so every Arabic string lands on it.

The currency mark

currency-font.css is an icomoon glyph font, keyed on [class^="currency-"]. ر.س is an icon, not Arabic text — which is why it sits left of the number in an LTR row without any bidi handling.
